# F0 spike: fluent2-egui client, go/no-go

Successor note to `docs/fluentgui-migration-plan.md`. Plan: `docs/reviews/fluent2-port-plan-2026-10.md` section 6. Issue: TheDancingDeveloper-org/email-rs#1.

## What landed in this spike

- `ClientCredential` on `email-client` (`with_credential`). A client can carry its own bearer token without writing `set_default_bearer_token`'s process-wide lock. The old function stays, because `email-desktop-fluent` still calls it. Wasm hosts must use the per-instance credential.
- `reqwest`'s `rustls-tls` feature is native-only. The wasm32 target depends on reqwest without rustls.
- `crates/email-ui` is **not** a workspace member. It builds only with `--features spike` (`cargo test -p` does not see it unless `--manifest-path crates/email-ui/Cargo.toml --features spike`). Default `cargo build --workspace` is unchanged.
- HtmlView here is a lossy tag strip over ten fixture bodies (plain, bold, link, list, quote, pre, table, Outlook-like, newsletter, empty). It is not html5ever/ammonia and it does not link fluent2-egui.

## What was not built

- No eframe shell, no fluent2-egui `v0.2.0` dependency, no native window, no wasm32 bundle. `fluent2-egui` tag `v0.2.0` exists upstream (`c822dad`). Pulling it plus eframe into this release line would change the default graph and fight the in-flight `v0.7.0` release. That shell is F1, after a go.

## wasm bundle size

Not measured. There is no wasm artifact. A size number without a built `email-web` bundle would be invented. Record it when F1 produces `email-web` (trunk or wasm-bindgen).

## HtmlView judgement

The ten fixtures stay readable as text (test `ten_fixture_mails_render_readable_text`). That does **not** meet the plan's L1 bar: block flow, inline colour, tables as grids, links via callback, `data:` images, selection, dark remap, AccessKit. A newsletter and an Outlook reply lose all layout. Text fallback is necessary but not sufficient for a reader.

## Go / no-go

**No-go for F1 implementation on this line until an operator accepts L1 as a fluent2-egui feature spike of its own.**

Reasons:

1. HtmlView is the critical path (plan section 3). The spike shows a text fallback only.
2. Wasm check of `email-client` is prepared (rustls gated, credential per instance) but not executed here: no wasm32 rustc target was assumed, and no bundle exists.
3. `v0.7.0` is mid-release. This spike does not touch the release workflow or version numbers (crate versions stay `0.7.0`).

Operator can still say **go** on the architecture: `email-ui` + `Backend` + per-instance credential is the right split. The missing piece is a real HtmlView, not another shell skeleton.
